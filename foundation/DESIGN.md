## 1. 产品定位与核心玩法

以**词缀（前缀 / 后缀 / 词根）**为组织单位,把四级单词按"同族"成组呈现。用户先看词缀的含义,再用 5 个左右的同族单词做**翻卡自测**,通过"先回忆、再核对"的方式完成记忆。

一句话玩法：**看词缀 → 猜词意 → 翻卡核对 → 下一组。**

与普通单词表的关键差异在于 `breakdown` 字段——用户看到的不只是 `review = 复习`,而是 `re-(再) + view(看) → 再看一遍 → 复习`。这是本产品的核心价值,不是可选装饰。

## 3. 信息架构与状态机

```
home（主界面）
  │
  ├─ 无今日记录      → 按钮「开始今日学习」 ┐
  ├─ 有未完成场次    → 按钮「继续今日学习 (3/7)」→ 直接恢复 learning
  └─ 今日已完成      → 按钮「再学一组」     ┘
                                            ↓
                              countSelect（选择数量）
                                            ↓
                              learning（第 i 页 / 共 M 页）
                                            ↓
                              complete（今日单词学完了）
                                    ├─ 回到主界面 → home
                                    └─ 添加单词   → countSelect（续接,不重复）
```

**关键约束**：「添加单词」不是重新开始,而是**在今日场次后追加新的页**,且必须跳过今日已学的单词。这由第 6 章的取词游标天然保证。

## 4. 界面设计

### 4.1 布局（桌面 ≥1024px）

垂直空间按 **1366×768 笔记本、浏览器可视高约 600px** 设计（v1.0 只约束了宽度，没有约束高度，这是本次修订的主要补齐项）：

```
┌──────────────────────────────────────────────────────────────┐
│ 第 1/2 页 · 已学 5 个单词 · 用时 03:12            [上一组]     │ ← 顶部栏 40px
├──────────┬───────────────────────────────────────────────────┤
│ ┌──────┐ │ ┌────┐┌────┐┌────┐┌────┐┌────┐                     │
│ │  re- │ │ │review│return│recall│repair│remind│              │ ← 单词卡区 5 列等分
│ │      │ │ │/rɪ../│/rɪ../│/rɪ../│/rɪ../│/rɪ../│              │   卡宽自适应 150~240px
│ │ 前缀 │ │ └────┘└────┘└────┘└────┘└────┘                     │   高度 ≤330px
│ │      │ │ ┌───────────────────────────────────────────────┐  │
│ │ 再、 │ │ │ v. 复习；回顾                                 │  │ ← 释义卡槽位
│ │ 重新 │ │ └───────────────────────────────────────────────┘  │   预留 88px
│ └──────┘ │                                   还有 2 个没看    │
│ 面板     │                                      〔下一组 →〕  │ ← 底部 56px
│ 200~240px│                                                   │
└──────────┴───────────────────────────────────────────────────┘
```

- **单词卡宽度不再固定 200px**（v1.0 的「5 张 × 200px + 面板 280px = 1280px」在 1024×768 和 1366×768 上必然挤压/溢出）。
  改为 5 列 `flex: 1 1 0` **等分**，卡宽随屏宽在 **150~240px** 之间浮动：1024 宽约 155px、1366 宽约 200px、1920 宽封顶 240px。
  **因此 1024×768 上 5 张卡无需换行**，换行只在 <1024px 才发生（§4.2）。
- **垂直预算（硬约束）**：顶部栏 40 + 卡片区 ≤330 + 释义卡槽 88 + 底部 56 + 间隙 16 = **≤530px**，
  在可视高 600px 的机器上一屏放下，**页面不出现纵向滚动条**。
- **词缀面板（最左，200~240px）**：`flex: 0 0 auto`，`≥1280px` 用 240px；`1024~1279px` 收窄到 200px。
  内容：词缀本体 + 类型徽标（前缀/后缀/词根）+ 中文含义 + 一句话说明。整页不变，切页时更新。
- **单词卡区（右侧，横排 5 张）**：`flex-wrap: wrap` + `min-width: 0`（老 flexbox 必须显式设置，否则长单词撑破卡片）。
- **释义卡（下方）**：**固定预留 88px 槽位**，初始 `visibility: hidden` + `opacity: 0`，点卡后淡入上移。
  预留槽位而非「按内容撑高」，是为了**零布局抖动（no reflow）**——既不推动整页，也不会在矮屏上把按钮挤出可视区。
- **「下一组」按钮（右下角）**：始终可点，不阻塞。

### 4.2 响应式档位（v1.1 由「两档」扩展为「四档」）

v1.0 只有「桌面横排 / <768px 竖排」两档，中间地带（**1024×768 与 1366×768 缩放 125%~150% 后等效 911~1093px**）没有定义，是最容易出问题的区间。

| 档位 | 触发条件 | 词缀面板 | 单词卡 | 释义卡 |
|---|---|---|---|---|
| **L 宽屏** | 宽 ≥1280 且 高 ≥620 | 左置 240px | 5 列等分（≈200~240px） | 底部预留槽 88px |
| **M 主流笔记本**（1366×768、1024×768） | 宽 1024~1279，或高 560~619 | 左置 200px | **5 列等分（≈155~200px）** | 底部预留槽 88px |
| **S 紧凑**（1024×768 高倍缩放、小平板） | 宽 768~1023，或高 <560 | **顶部单行摘要**（点按展开） | 3+2 换行 | 底部槽位 88px，卡片区内部滚动 |
| **XS 窄屏/竖屏** | 宽 <768 | 顶部单行摘要 | 竖排 1 列，占满宽度 | **跟随被点击卡片**内联展开 |

**档位判定规则**：宽度档与高度档**取更保守的一档**（`1366×768` 可视宽 1366 判 L、可视高 600 判 M → 实取 **M**）。
这样老笔记本默认落到 M 档，不必靠用户手动缩放。

XS 档保留 v1.0 的结论且理由不变：竖排时「底部弹出」会让用户看不清卡片与释义的对应关系，因此释义卡紧跟在被点击的单词卡下方。

### 4.3 主界面

居中：产品名 + 一句说明 + 主按钮（文案随今日状态变化,见第 3 章）+ 今日状态行（`今日已学 7 个单词 · 2 个词缀`）。

### 4.4 数量选择页

- 预设按钮：`5` `10` `15` `20`
- 自定义：`− / +` 步进（步长 1,范围 1~50）
- **实时预览文案**（重要）：
  - `共 7 个单词,分 2 组（第 2 组 2 个）`
  - 剩余新词不足时：`剩余新词仅 4 个,本次将学完`
- 「开始学习」按钮

### 4.5 完成页

- 居中大字：**今日单词学完了**
- 统计行：`今天学了 7 个单词、2 个词缀,用时 06:41`
- 两个按钮：`回到主界面`（次要样式） / `添加单词`（主要样式）

## 5. 卡片翻面交互规范

卡片有三种状态：`hidden`（释义卡未出现）/ `front`（正面）/ `back`（背面）。

### 5.1 状态表

| 卡片 | 正面内容 | 背面内容 |
|---|---|---|
| 单词卡 | 单词 + 音标 | 词根拆分 + 助记（`breakdown`） |
| 释义卡 | 词性 + 中文释义 | 例句 + 例句翻译 |

### 5.2 点击行为

| 触发 | 结果 |
|---|---|
| 点击单词卡（释义卡为 `hidden`） | 释义卡从下方滑出,显示正面。**单词卡不翻面** |
| 点击单词卡（释义卡已显示） | 单词卡翻面（`front` ⇄ `back`）,可反复翻回 |
| 点击释义卡 | 释义卡翻面（`front` ⇄ `back`）,可反复翻回 |
| 点击另一张单词卡 | 释义卡切换到该词的内容,回到 `front`；前一张单词卡的翻面状态保留 |

### 5.3 状态标记

- 单词卡一旦被点击过,右上角出现一个小圆点,表示"这词我看过了"。
- 翻面为**可逆**操作,但 `flipped` 布尔值一经置 `true` 即永久保留（用于进度统计与页内提示）。
- 翻面为**本页内状态**,切到下一页时重置为 `hidden`；通过「上一组」返回时恢复。

### 5.4 进度提示

右下角「下一组」按钮旁边显示 `还有 2 个单词没看`；全部看过则显示 `本组已看完整 ✓`。按钮本身在任何情况下都可点击。

### 5.5 键盘快捷键

| 按键 | 行为 |
|---|---|
| `1`~`5` | 等价于点击第 n 张单词卡 |
| `空格` | 翻面当前聚焦的卡（无聚焦则作用于第 1 张单词卡） |
| `→` / `Enter` | 下一组 |
| `←` | 上一组 |

### 5.6 翻面动画的降级（v1.1 新增）

翻面**效果**是产品的一部分，翻面**动画**不是。动画能力在旧电脑上并不保证存在，因此定义三级降级：

| 级别 | 触发条件 | 表现 |
|---|---|---|
| A 3D 翻面 | `@supports (transform-style: preserve-3d)` 且探测到 `transform` 可用 | `rotateY(180deg)` 3D 翻面，0.45s |
| B 淡入切换 | 不支持 3D（`preserve-3d` 无效、驱动异常、`--disable-gpu`） | 正反面**淡出淡入**（150ms `opacity`），无 3D；卡片尺寸与交互完全一致 |
| C 直接切换 | `prefers-reduced-motion: reduce`，或探测到低端机（`hardwareConcurrency ≤ 2`） | 瞬间切换，**无任何过渡**；交互与状态标记照旧 |

三级降级只影响观感，不影响 §5.1 的状态表与 §5.2 的点击行为——**所有验收项在 B/C 级下同样成立**。

## 6. 取词与分组算法（核心）

因为允许任意数量,必须解决"末组不满 5 个词"以及"下次从哪继续"的问题。方案是**全局取词游标**。

### 6.1 数据流

把学习单元数据展平成一个线性流（同单元的词连续排列；本节的 `AFFIXES` 在 v1.1 即 `CET4_UNITS`，见 `TECH_SPEC.md` §3.1）：

```
[re-: review, return, recall, repair, remind] [pre-: preview, predict, ...] [port: ...] ...
```

### 6.2 取词

**注意：`Array.prototype.flatMap` 是 ES2019 特性，基线浏览器不可用（§14.2），因此下面的 ES5 版本才是可落地写法**：

```js
// UNIT_STREAM 在构建期由 build_units.py 展平并排好序（见 TECH_SPEC.md §4.3）
function takeWords(count) {
  var start = loadCursor();                          // 全局游标
  var slice = UNIT_STREAM.slice(start, start + count); // 可能短于 count
  saveCursor(start + slice.length);                  // 游标前移
  return groupByUnit(slice);                         // 按学习单元切页
}

function groupByUnit(slice) {
  var pages = [], i, cur = null;
  for (i = 0; i < slice.length; i++) {
    var item = slice[i];
    if (!cur || cur.unitId !== item.unitId) {        // 只合并「相邻同单元」
      cur = { unitId: item.unitId, wordIds: [] };
      pages.push(cur);
    }
    cur.wordIds.push(item.wordId);
  }
  return pages;
}
```

- `groupByUnit` 只做**相邻同单元**合并,因此结果必然保持顺序（`Array.prototype.map`/`forEach` 可用，但 `flatMap` 不可用）。
- 游标永远不会回退,所以**同一批单词不会被重复发放**,「添加单词」天然续接、不重不漏。
- 若某一页正好是某单元的后半段（例如 `pre-` 的第 3~5 个词）,词缀面板照常显示该词缀介绍——这不影响教学完整性。
- 页面→面板的映射（含 mix 单元只显示本页出现的 chip）见 `TECH_SPEC.md` §4.3。

### 6.3 示例

假设 `pre-` 有 5 个词,用户第一次选 7：

| 页 | 词缀 | 单词数 |
|---|---|---|
| 1 | `re-` | 5 |
| 2 | `pre-` | 2 |

用户点「添加单词」再选 6：

| 页 | 词缀 | 单词数 |
|---|---|---|
| 3 | `pre-` | 3（即 `pre-` 的第 3~5 个词） |
| 4 | `port` | 3（即 `port` 的第 1~3 个词） |

> 本例中的 `re-` / `pre-` / `port` 是**示意名**。实际单元 id 形如 `pre:re`（前缀）、`root:port`（词根）、`suf:tion`（后缀）、`mix:007`（微小词根合并组），
> 逻辑完全一致：**页 → 单元**的映射发生在取词时，与 v1.0 的「页 → 词缀」等价。

### 6.4 剩余不足

剩余新词少于所请求数量时：取走全部剩余词,并在进入学习页前提示 `今日新词已学完,本次共 4 个`。若剩余为 0,数量选择页整体置灰并显示 `所有单词都学完啦,后续版本将提供复习模式`。

## 7. 数据结构

### 7.1 词缀数据（`data/words.js`）— 概念示意

```js
window.CET4_UNITS = [   // v1.1 的实际全局名（原 CET4_AFFIXES）；字段口径以 TECH_SPEC.md §3.1 为准
  {
    id: "re",                        // 唯一标识,用于取词与分组
    affix: "re-",
    type: "前缀",                     // 前缀 | 后缀 | 词根
    meaning: "再、重新；向后",
    note: "常表示重复或返回,置于动词、名词前。",
    words: [
      {
        id: "review",
        word: "review",
        phonetic: "/rɪˈvjuː/",
        pos: "v.",
        meaning: "复习；回顾",
        breakdown: "re-(再) + view(看) → 再看一遍 → 复习",
        example: "I review the new words every evening.",
        exampleZh: "我每天晚上复习新单词。"
      }
      // ... 本词缀共 5 个词
    ]
  }
  // ...
];
```

**约定**（v1.1 与数据实况对齐，详见 `TECH_SPEC.md` §3.1–§3.2）：
- 本节的结构是**概念示意**。实际运行期实体是**学习单元 Unit**（`root:` / `pre:` / `suf:` / `mix:` 四类），
  因为实测词根规模极不均（57 个词根只带 1 词、`sist` 带 38 词），「一个词缀固定 5 词」不成立。
  Unit 的字段与生成算法以 `TECH_SPEC.md` §3.1 / §3.2 为准；本节的 `breakdown` / `affix` / `meaning` 语义不变。
- `words` 数组内的词**必须连续存放在一起**（取词算法依赖这一点）；单元可含 1~5 词，超长单元被拆成同词根的多页。
- 卡片标识统一用 `${unitId}#${word}`,避免跨单元同词冲突。
- **数据规模（v1.1 修正）**：不再是「20 个词缀 × 5 词 = 100 词」的手写原型。
  现有流水线已产出 **1487 个可用词（312 个 Unit）**，而运行时开销与总词数无关（只渲染当前页 5 张卡），
  因此 **MVP 直接全量上线**，无需「先 100 词跑通再扩量」的过渡。

### 7.2 今日场次（localStorage `cet4.session.v1`）

```js
{
  date: "2026-02-14",
  startedAt: 1739520000000,
  pages: [
    { unitId: "pre:re",  wordIds: ["review","return","recall","repair","remind"] },
    { unitId: "pre:pre", wordIds: ["preview","predict"] }
  ],
  currentPage: 0,
  cardState: {                                  // key = `${unitId}#${word}`
    "pre:re#review": { revealed: true, flipped: true }
  },
  completed: false
}
```

场次自包含全部页与卡片状态,**刷新后可直接恢复,无需重新取词**（游标已前移,重新取词会漏词）。
字段名与 `TECH_SPEC.md` §4.4 一致：`affixId` 更名 `unitId`，卡片键改为 `${unitId}#${word}`，并增加 `schema: 1`。

### 7.3 其他存储键

| 键 | 内容 |
|---|---|
| `cet4.cursor.v1` | 全局取词游标（number） |
| `cet4.session.v1` | 今日场次对象 |
| `cet4.history.v1` | `[{ date, words, affixes, minutes, completed }]`,仅供主界面展示连续天数（可选） |
| `cet4.meta.v1` | `{ dataVersion }`；与词库 `CET4_META.version` 不一致时清游标与场次（词库重建后游标语义会漂移） |

**存储可用性兜底（v1.1 新增）**：老电脑上 `localStorage` 可能不可用——浏览器处于无痕模式（访问即抛 `SecurityError`）、
系统/组策略禁用本地存储、或 `file://` 下被安全设置拦截。因此**所有读写必须包在 `try/catch` 内**，
失败时自动降级为**内存态存储**（本次会话内一切正常，刷新后进度丢失），并在主界面用一行小字提示
`本机禁用了本地存储，刷新后进度会丢失`。**绝不允许因为存储异常导致白屏或按钮失灵。**

### 7.4 跨天处理

进入 `home` 时检查 `session.date`：
- 等于今天 → 按第 3 章三态判断。
- 不等于今天 → 把旧场次归档进 `history`（若 `completed` 为 false 也照常归档,不惩罚用户）,重置今日场次。**游标不清空**,保证取词连续性。

## 8. 应用状态与渲染

单一状态对象 + 单一 `render(state)` 函数,不做组件拆分。

> **v1.1 注**：本章代码为**示意伪代码**；实际实现必须写成 **ES5 语法**（`var`，不用 `const`/箭头函数，见 §9、§14.2）。
> 另外「整体重建 DOM」的粒度按 `TECH_SPEC.md` §4.8.3 细化：**点卡只切类名**（不重建），**换页只重建卡片区**，
> 只有**切换视图**才整体重建——这是老机器上避免无谓重排与 GC 压力的关键。

```js
var state = {
  view: "home",           // home | countSelect | learning | complete
  session: null,          // 见 7.2
  draft: { count: 5 },    // 数量选择页的临时值
  focus: null,            // 当前聚焦的卡片 key
  tick: 0                 // 计时器刷新用
};

function render(state) { /* 按 state.view 分支；粒度见 TECH_SPEC §4.8.3 */ }
```

- 事件用**委托**：在容器上监听一次 `click`,通过 `data-action` / `data-card` 属性分发（委托同时更省内存）。
- 状态变更后 `render()` + `saveSession()`；`saveSession()` 内部必须 `try/catch`（§7.3）。
- 计时器每秒刷新时**只改一个文本节点**，不要 `innerHTML` 重建顶部栏。

## 10. 样式要点

CSS 只有**一个文件、无预处理器、无构建**，因此写法必须限定在 2015 年可用的特性集合内（§14.3 有完整白/黑名单）。

- **只做「合成层」动画**：过渡属性**只用 `transform` 与 `opacity`**。这两个属性不触发重排与重绘，CPU 与集显机器都能跑顺；
  一律**不**对 `width` / `height` / `top` / `left` / `box-shadow` / `filter` 做过渡（这些会逐帧重排或重绘，是老机器卡顿的主因）。
- **翻面动画**：外层 `perspective: 1000px`，内层 `transform-style: preserve-3d` + `transition: transform .45s`，
  正反面 `backface-visibility: hidden`，**全部补 `-webkit-` 前缀**（Safari 9 必须），背面初始 `rotateY(180deg)`。
  用 `@supports (transform-style: preserve-3d)` 包裹；不支持时走 §5.6 的 B 级降级（淡入切换）。
- **长单词自适应**：**不用 `clamp()`**（Chrome 79+ 才有）。改为构建期按字符长度打标（`≥10` 字符 → `.w-long`，`≥13` → `.w-xlong`），
  渲染时挂类名降一档字号，并统一 `word-break: break-word` + `overflow-wrap: break-word` + `hyphens: auto` 兜底长词。
- **释义卡出现**：**固定预留 88px 槽位**（§4.1），初始 `visibility: hidden` + `opacity: 0` + `transform: translateY(6px)`，
  点卡后切到 `visible / opacity:1 / translateY(0)`。**不用 `max-height` 过渡**——那会逐帧重排，矮屏上还会把按钮挤出可视区。
- **布局只用 flexbox（带旧语法前缀）**：`display: -webkit-box; display: -webkit-flex; display: flex;`。
  **不用 CSS Grid**（Safari 10.1+/Edge 16+ 才有）、**不用 flex `gap`**（Chrome 84+，改用子元素 `margin`）、
  **不用 CSS 变量 `var()`**（Safari 9.0/Edge 12~14 不支持，改用字面量，顺带更省）。
- **字体与图形**：只用系统字体栈（`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`），
  **不引 Web 字体、不用图片、不用图标库**——图标用文字符号（`→ ✓ ·`）或纯 CSS 画。整站零外部请求。
- **配色**：单一强调色 + 中性灰阶。正面浅色、背面浅暖色，一眼可辨是否已翻面。
  文字与底色对比度 ≥ 4.5:1（老笔记本屏幕可视角差、色彩偏差大，低对比度会看不清）。
- **尺寸单位用 `px` 为主**：老机器上浏览器缩放 125%/150% 很常见，`px` + 媒体查询的表现可预期；`rem` 仅用于字号。
  **不用 `vh`/`vw` 做关键高度**（移动端地址栏与老桌面浏览器的 `vh` 行为不一致），关键区高度用 `px` + `flex` 收缩。
- **可访问性**：卡片用 `<button>` 而非 `<div>`，保留焦点环，`aria-pressed` 标记翻面状态，
  键盘可达（§5.5）——这条同时是「旧机器触控板不方便时仍可纯键盘使用」的保障。

## 14. 兼容性、屏幕适配与轻量化基线（v1.1 新增）

本章是**强制基线**：§4 布局、§5 翻面、§9 文件结构、§10 样式、§11 边界、§12 验收均以本章为准。

### 14.1 目标机器画像

「大部分电脑」按**中国高校与家庭里最常见的存量机器**定义，而不是新买的高配机：

| 维度 | 目标下限 | 说明 |
|---|---|---|
| 操作系统 | Windows 7 SP1 及以上（含 Win10/Win11）、macOS 10.11+ | 覆盖 2015 年后的存量机器 |
| 内存 | 2GB | 页面内存占用目标 < 50MB |
| 显卡 | **集显 / 无硬件加速** | 不做任何依赖 GPU 的效果（模糊、阴影动画、滤镜、3D 场景） |
| CPU | 双核 1.6GHz | 无逐帧 JS 动画，交互全部交给 CSS 合成层 |
| 浏览器 | **Chrome 49+ / Firefox 45+ / Safari 9+ / Edge 12+**，以及国内 360、QQ、搜狗浏览器的**极速（Chromium）模式** | 见 §14.2 |
| 屏幕 | **1366×768** 为设计基线，**1024×768** 不溢出 | 见 §4.2 |
| 缩放 | 100% / 125% / 150% | 等效视口宽度会缩到 ~911px，必须靠档位兜住 |
| 网络 | **不需要网络**（离线可用） | 零外部请求，见 §14.3 |

> **明确不追求**：IE11 及以下（IE 内核不支持 `transform-style: preserve-3d`，需另做一整套 2D 布局与 CSS 兜底，性价比过低）。
> IE 内核下只保证「不白屏、给出升级提示」，见 §14.4。

### 14.2 浏览器能力基线（决定代码能写什么）

| 能力 | 基线内是否可用 | 采用决策 |
|---|---|---|
| ES5（`var`/`function`/`JSON`/`forEach`/`classList`） | ✅ 全部支持 | **只用 ES5**，不用 ES6+ 语法 |
| ES6+（`let`/`const`/箭头函数/模板串/解构/`class`） | ❌ Chrome 49 部分、Edge 12 多数不支持 | **禁用**，由静态守卫脚本强制 |
| `Array.prototype.includes` / `padStart` / `Object.entries` | ❌ 部分基线浏览器缺失 | 禁用，改用 `indexOf` / 手写补零 / `Object.keys` |
| CSS `transform` + `transition`（含 `-webkit-`） | ✅ | 动画唯一手段 |
| `transform-style: preserve-3d` | ✅（IE 内核除外） | 用 `@supports` 包裹，另备 2D 降级（§5.6） |
| `@supports` | ✅ | 作为降级的一等机制 |
| CSS 变量 `var()` | ⚠️ Safari 9.0 / Edge 12~14 不支持 | **不用**，写字面量 |
| CSS Grid / flex `gap` / `clamp()` | ❌ 基线内缺失 | **禁用**（改用 flex + margin + 长度分档字号） |
| `prefers-reduced-motion` | ⚠️ 老浏览器不识别 | 可用作**渐进增强**（不识别时该媒体查询被忽略，无副作用） |
| `navigator.hardwareConcurrency` | ⚠️ 部分缺失 | 探测前先判存在，缺失时不做低端机判断（默认走 A 级动画） |
| `localStorage` | ⚠️ 可能被禁用或抛异常 | `try/catch` + 内存兜底（§7.3） |

**核心判断**：能覆盖 2015 年后几乎所有主流浏览器的代价，仅是把代码写成 ES5 风格与少用几个新 CSS 特性——
**体积为零、构建步骤为零**，因此这笔交易划算，没有理由只支持最新浏览器。

### 14.3 轻量化设计（设计原则，不是口号）

轻量化的**真正瓶颈不是数据体积**（实测词库压缩后仅 77KB，见 `TECH_SPEC.md` 附录 A），而是**旧浏览器的语法与渲染能力**。因此按收益排序：

1. **零依赖、零构建、零请求**：无框架、无 CDN、无 Web 字体、无图片、无图标库。整站总载荷 **< 200KB**，断网可用。
2. **ES5 语法**：换取 2015 年后的全量浏览器覆盖，成本为零（见 §14.2）。
3. **只做合成层动画**（`transform` / `opacity`）：老集显机器不掉帧，也不触发重排。
4. **零布局抖动**：释义卡固定预留槽位（§4.1），点卡不推动页面、不重排。
5. **局部更新优先**：翻卡只切类名，**只有换页/换视图才整体重建 DOM**（`TECH_SPEC.md` §4.8）。
6. **数据一次加载、按需渲染**：总词数只影响 `<script>` 解析一次，与每帧渲染量无关。
7. **不做**：预加载动画、骨架屏、内置字体、图片背景、粒子/模糊特效、第三方统计脚本。

### 14.4 能力探测与降级阶梯

启动时按顺序探测，结果以类名挂在 `<body>` 上，CSS/JS 据此分支（探测代码 ≤ 20 行）：

```
body.no3d      → §5.6 B 级：2D 淡入切换
body.reduce   → §5.6 C 级：无过渡
body.perf-low → 关闭非必要过渡、缩短动画时长（探测失败则不加此类）
body.nostore  → 内存态存储 + 主界面提示（§7.3）
body.noes5    → 极旧/IE 内核：只渲染一行「请用 Chrome / Firefox / Edge 打开」的静态提示，不白屏
```

- `body.noes5` 的判定用**不需要 ES6 语法的探测器**：在 ES5 脚本里判断 `document.querySelector` / `addEventListener` / `JSON` 是否存在，
  并用 `try { eval('()=>{}') } catch(e)` 的方式判断箭头函数是否可解析。**必须放在 ES5 脚本中**，否则旧浏览器在解析阶段就报错、连提示都显示不出来。
- 另提供**诊断模式**：URL 加 `?diag=1`（或 `localStorage` 无法写入时自动提示）在页面底部显示
  `浏览器版本 / 视口尺寸 / DPR / 3D 支持 / 存储可用性`，用于在用户机器上远程判断问题，无需开发者工具。

### 14.5 屏幕适配（对齐 §4.2，此处给出量化依据）

| 场景 | 物理分辨率 | 浏览器可视区（扣地址栏/书签栏/任务栏） | 等效档位 |
|---|---|---|---|
| 老台式/老笔记本 | 1024×768 | ≈ 1024×600 | **M** |
| 主流旧笔记本 | 1366×768 | ≈ 1366×600 | **M**（宽度判 L、高度判 M，取保守） |
| 旧笔记本 125% 缩放 | 1366×768 | ≈ 1093×480 | **S** |
| 旧笔记本 150% 缩放 | 1366×768 | ≈ 911×400 | **S** |
| 新机 | 1920×1080 | ≈ 1920×900 | **L** |

结论：**必须预设「可视高度只有 400~600px」**，这正是 §4.1 垂直预算 ≤530px 与 §4.2 高度档的由来。

### 14.6 交付形态：多文件源码 + 单文件便携版

| 形态 | 用途 | 说明 |
|---|---|---|
| 源码多文件（`index.html` + `styles.css` + `app.js` + `data/words.js`） | 开发与维护 | 结构清晰，便于 diff 与排查 |
